# تحليل مشكلة تخزين المهارات في الجلسات

## 1. المشكلة الأساسية

### 1.1 `skillId` دائمًا فارغ
في `_recordGoalSession()` (سطر 246 من `sessions_screen.dart`):
```dart
skillId: '',  // ثابت دائمًا
```
رغم أن جدول `sessions` في قاعدة البيانات يحتوي على عمود `skill_id`، إلا أنه لا يُستخدم أبدًا. المهارات مخزنة كنص فقط في حقل `notes`.

### 1.2 `notes` كنص مسطح (flat string)
عند حفظ الجلسة، يُكتب `notes` كالتالي:
- بلا خطوات: `"تقييم هدف: ${goal.goal} - النتيجة: $status"`
- بخطوات مُقيّمة: `"${s.title}: ${s.status} | ${s.title}: ${s.status}"`
- غير مُقيّمة: `"تقييم: $status"`

هذا النص:
- غير قابل للاستعلام (لا يمكن COUNT/SELECT حسب المهارة)
- غير قابل للمقارنة (اختلافات كتابية محتملة)
- غير مرتبط بأي ID للمهارة
- يختلط مع ملخص السرد العلاجي

### 1.3 `successRate` دائمًا 0
عند إنشاء الجلسة في `_recordGoalSession()`، `successRate` يأخذ القيمة الافتراضية `0` رغم وجود `quickResult` (`متقن`, `بمساعدة`, `يحتاج إعادة`) الذي يمكن تحويله لرقم.

النتيجة: جميع المقاييس العددية معطلة:
- تقرير PDF: `strong=0`, `needsSupport=total`
- لوحة التحكم: متوسط الأداء `0%`
- ملف الطالب: `نجاح 0%` دائمًا
- شاشة التقارير: `0%`

## 2. بنية البيانات الحالية

```
sessions
├── id (PK)
├── plan_id → training_plans.id  (معرف الهدف)
├── skill_id                      (دائمًا '')
├── notes                         (نص مسطح للمهارات)
├── quick_result                  (متقن/بمساعدة/يحتاج إعادة)
├── success_rate                  (دائمًا 0)
├── card_title                    (نص الهدف)
├── practice_items                (الأنشطة)
└── ...

goal_skill_steps
├── id (PK)
├── goal_id → training_plans.id
├── title
├── status                        (متقن/بمساعدة/لم يبدأ/يحتاج إعادة)
├── last_session_id               (آخر جلسة — دائمًا فارغ)
└── ...
```

**لا توجد علاقة مباشرة بين `sessions` و `goal_skill_steps`.** `sessions.notes` يحتوي نسخة نصية من حالة المهارات ولكن بدون ID.

## 3. ماذا تحتاج التقارير؟

التقارير الحالية (`pdf_service.dart`) تظهر:
1. **جدول الجلسات**: `cardTitle`, `practiceItems`, `successRate`, `startedAt`
2. **ملخص الأداء**: عدد الجلسات، نسبة الأداء (successRate)، أداء قوي (≥80)، يحتاج دعم (<60)
3. **الخطة التدريبية**: `plan.goal` + `plan.progress`
4. **تقييم النطق**: `evaluation.letter` + `position` + `errorType` + `score`

**لا تظهر المهارات (`goal_skill_steps`) في التقرير أبدًا.** ولا تظهر `notes` (نتائج المهارات النصية).

لإظهار نتائج المهارات في التقرير، تحتاج التقارير إلى:
- لكل جلسة: قائمة بالمهارات المُقيّمة ونتائجها
- لكل هدف: تقدم على مستوى المهارات

## 4. هل يمكن قراءة المهارات من `notes`؟

نظريًا: يمكن استخدام RegExp لاستخراج `"${title}: ${status}"` من النص.

مخاطر:
- الكتابة غير موحدة (قد تختلف المهارة بين الجلسات)
- لا يمكن الربط بـ `goal_skill_step.id` للمقارنة عبر الزمن
- حساس للأخطاء الإملائية
- الأداء ضعيف مع عدد كبير من الجلسات
- لا يعمل أصلًا إذا لم تكن الجلسة تحتوي على خطوات (no steps)

**لا يُنصح به.**

## 5. تحليل نظام XP

`_grantXp()` يُستدعى من `saveSession()` عند حفظ الجلسة:
- `متقن` → +2 XP
- `بمساعدة` → +1 XP
- غير ذلك → 0 XP

XP:
- لا يظهر في أي تقرير علاجي
- لا يظهر في ملف الطالب (بعد إعادة التصميم)
- موجود فقط في جدول `rewards` للعرض التحفيزي لولي الأمر
- لا يؤثر على `successRate` أو أي مقياس سريري

**الخلاصة: XP معزول تمامًا عن التقارير.** لا حاجة لتعديله.

## 6. خطة الإصلاح المقترحة

### المرحلة 1 — إصلاح `successRate` (فوري، آمن، بدون DB migration)
**خطورة: عالية (bug في التقارير)** | **تأثير: فوري** | **تغيير DB: لا**

**الإجراء:**
في `_recordGoalSession()`، تعيين `successRate` حسب `quickResult`:
- `'متقن'` → 100
- `'بمساعدة'` → 60  
- `'يحتاج إعادة'` → 20
- غير ذلك → 0

**التحقق:** `flutter analyze` يمر، `flutter test` يمر، تقارير PDF تظهر الأرقام الصحيحة.

### المرحلة 2 — إضافة جدول `session_skill_results` (مخطط له)
**خطورة: منخفضة (إضافة جدول جديد)** | **تأثير: تراكمي** | **تغيير DB: نعم (إضافة فقط)**

**التصميم:**
```sql
CREATE TABLE session_skill_results (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL,
  goal_skill_step_id TEXT NOT NULL,
  goal_id TEXT NOT NULL,
  step_title TEXT NOT NULL,
  result TEXT NOT NULL DEFAULT 'لم يبدأ',
  created_at TEXT NOT NULL,
  FOREIGN KEY(session_id) REFERENCES sessions(id)
);
```

**مزايا:**
- لا تغيير على الجدول القديم (sessions)
- لا فقدان بيانات
- يمكن الاستعلام بسهولة (COUNT, GROUP BY, WHERE)
- الربط بـ `goal_skill_step_id` يتيح مقارنة عبر الزمن
- يمكن إضافة التقرير لاحقًا دون تكسير

**التكامل:**
- في `_recordGoalSession()`: بعد إنشاء الجلسة، احفظ كل `GoalSkillStep` في جدول `session_skill_results`
- إضافة `sessionSkillResults()` في `SanadRepository`
- إضافة getter في `AppProvider` (اختياري)

### المرحلة 3 — تحديث تقارير PDF
- إضافة جدول المهارات لكل جلسة في التقرير
- استخدام `sessionSkillResults` بدل `notes`
- استخدام `successRate` الصحيح بعد إصلاح المرحلة 1

## 7. المخاطر

| الإجراء | المخاطرة | مستوى الخطورة |
|---|---|---|
| إصلاح `successRate` | لا يوجد — تغيير runtime فقط | منخفض جدًا |
| إضافة جدول جديد | لا يوجد — إضافة فقط | منخفض جدًا |
| ربط `session_skill_results` بـ `sessions.id` | لا يوجد FK issue | منخفض جدًا |
| قراءة من `notes` | خطأ إملائي، اختلافات كتابية | عالي |
| تغيير `notes` format | يكسر أي كود يقرأ من notes | عالي |

## 8. الخلاصة

1. **Bug عاجل**: `successRate` دائمًا 0 — يجب إصلاحه فورًا (إصلاح سطر واحد)
2. **إضافة جدول**: `session_skill_results` — آمن وموصى به للتقارير المستقبلية
3. **XP**: لا تأثير له على التقارير — لا حاجة لتعديل
4. **`notes`**: يبقى كنص مسطح للملخص فقط — لا يُعتمد عليه للبيانات المنظمة
