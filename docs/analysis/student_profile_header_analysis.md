# تحليل الجزء العلوي من ملف الطالب — Header + Summary + Student Overview

---

## 1. ما الذي يعرضه الآن؟

الجزء العلوي (أول 85 سطرًا في `build()`) مكون من 3 عناصر رئيسية:

### 1.1 زر الرجوع + `_StudentOverview` (سطر 70-83)
```
[رجوع لاختيار طالب آخر]  ← زر دائم (إلا لولي الأمر)
─────────────────────────────────
🕐 (CircleAvatar)  اسم الطالب        [status Chip]
                   اسم المركز
                  (برامج الطالب إن وُجدت)
العمر  |  التشخيص
ولي الأمر  |  رقم ولي الأمر
اسم المستخدم (البريد)
ملاحظات الملف (إن وُجدت)
```

**المصادر:**
- `student.name`, `student.age`, `student.diagnosis`, `student.parentName`, `student.parentPhone`, `student.portalEmail`, `student.notes` — من `selectedStudent`
- `app.currentCenter?.name` — المركز
- `app.programsForStudent()` — البرامج المسجلة

### 1.2 `_ProfileSummary` (سطر 85 — 6 StatTile)
```
┌─────────────────┬─────────────────┬─────────────────┐
│   حالة التقييم  │  الأهداف النشطة │  الأهداف المتقنة │
│   مقيّم/يحتاج   │        3        │        1        │
├─────────────────┼─────────────────┼─────────────────┤
│  نسبة التحسن     │  عدد الجلسات    │  واجبات للمراجعة │
│    45%          │      12         │        2        │
└─────────────────┴─────────────────┴─────────────────┘
```

**المصادر:**
- `app.studentAssessmentStatus` ← `clinicalAssessments.any((a) => a.studentId == selectedStudent.id)`
- `app.activeGoalCount` ← `plans.where((p) => p.progress < 100).length`
- `app.masteredGoalCount` ← `plans.where((p) => p.progress >= 100).length`
- `app.studentGoalImprovementRate(student.id)` ← متوسط `progress` للخطط بهذا الطالب
- `app.sessions.length`
- `app.pendingHomeworkReviewCount` ← `exercises.where((e) => e.status == 'completed_by_parent').length`

### 1.3 أول CollapsibleCard — التقييم العلاجي (سطر 87-93)
```
[▼] التقييم العلاجي  (3)
آخر تقييم: 2026-05-10
```

بعد التوسيع: يعرض آخر 3 تقييمات علاجية مع findings.

## 2. البيانات المكررة بين المكونات الثلاثة

### 2.1 تكرار صريح

| المعلومة | تظهر في |
|---|---|
| **اسم الطالب / المركز** | `_StudentOverview` فقط ← لا تكرار |
| **حالة التقييم** | `_ProfileSummary` + أول CollapsibleCard (عنوانه + summary فيه "آخر تقييم: ...") |
| **الأهداف النشطة/المتقنة** | `_ProfileSummary` + عنوان CollapsibleCards الثاني والثالث (بـ count + summary) |
| **عدد الجلسات** | `_ProfileSummary` + قسم "الجلسات السابقة" (لاحقًا) |
| **الواجبات للمراجعة** | `_ProfileSummary` + قسم "الواجبات المنزلية" |

ملاحظة: كل CollapsibleCard يعرض `count` و `summary` في شريط العنوان حتى قبل التوسيع.
هذا يعني أن **`_ProfileSummary` يعرض نفس الأرقام التي تظهر في عناوين البطاقات أسفله**:

```
_ProfileSummary:  الأهداف النشطة: 3
  ↓ تطابق
Card title:       الأهداف النشطة (3) - 3 أهداف قيد المتابعة
```

### 2.2 تكرار غير مباشر

| المعلومة | تظهر في `_StudentOverview` | تظهر في `_ProfileSummary` |
|---|---|---|
| **التشخيص** | `_CompactInfoTile` | لا يظهر |
| **البرامج** | Wrap من `programsForStudent()` | لا يظهر |
| **ولي الأمر / الهاتف** | `_CompactInfoTile` | لا يظهر |
| **نسبة التحسن** | لا يظهر | StatTile (متوسط progress) |
| **المتابعات المفتوحة** | لا يظهر | لا يظهر (تظهر كـ CollapsibleCard منفصل) |

## 3. تحليل القيمة لكل قطعة بيانات في الجزء العلوي

### 3.1 البيانات الأساسية (مهمة دائمًا — في `_StudentOverview`):
- **الاسم** — ضروري لتأكيد الطالب
- **المركز** — مفيد لكن ليس عاجلاً
- **الحالة** (Chip) — مفيد (نشط/منقول/محذوف)
- **البرامج** — مفيد لكن ليس عاجلاً

### 3.2 بيانات عالية القيمة للأخصائي (تحتاج ظاهرة فورًا):
- **آخر جلسة** → التاريخ + quickResult **(غير موجود في الجزء العلوي!)**
- **المتابعات المفتوحة** → عددها **(غير موجود!)**
- **حالة التقييم** → موجود (مقيّم/يحتاج تقييم)
- **عدد الأهداف النشطة** → موجود
- **عدد الواجبات للمراجعة** → موجود

### 3.3 بيانات منخفضة القيمة للأخصائي (يمكن تأجيلها لأسفل):
- **ولي الأمر ورقمه وهاتفه** — يحتاجها الأخصائي أحيانًا لكن ليست أولوية عند فتح الملف
- **اسم المستخدم (البريد)** — نادرًا ما يحتاجه
- **ملاحظات الملف** — نادرًا ما تكون مطلوبة أولاً

### 3.4 "نسبة التحسن" في `_ProfileSummary` — مشكلة
`studentGoalImprovementRate` هو **متوسط progress لكل الخطط**، وليس نسبة تحسن حقيقية.
```
مثال: خطتان (80% + 20%) → التحسن = 50%
لكن هل هذا صحيح؟ لا، لأن 50% لا تعبر عن تحسن فعلي.
```
هذه المعلومة **مضللة** ويجب تمييزها كـ "متوسط تقدم الأهداف" لا "نسبة التحسن".

## 4. ماذا يمكن دمجه داخل بطاقة ملخص واحدة (بدون تغيير المنطق)؟

يمكن استبدال `_StudentOverview` + `_ProfileSummary` + زر الرجوع ببطاقة واحدة تسمى **`_StudentHeaderCard`** تحتوي على 3 صفوف فقط:

### التصميم المقترح:

```
[← رجوع]
┌──────────────────────────────────────────────────────┐
│  🕐  |  اسم الطالب                          [status] │
│      |  آخر جلسة: 2026-06-10  |  متقن              │
│      |  المركز: المركز الأهلي                       │
│─────────────────────────────────────────────────────│
│  [المتابعات: 2]  [للمراجعة: 1]  [المقيم: مقيّم]    │
│  [الأهداف: 3]    [الجلسات: 12]   [التقدم: 45%]     │
│─────────────────────────────────────────────────────│
│  البرامج: [نطق] [تخاطب]                             │
└──────────────────────────────────────────────────────┘
```

**المصادر (دون تغيير أي منطق):**

| الحقل | المصدر الحالي |
|---|---|
| الاسم | `student.name` |
| الحالة Chip | `student.status` |
| آخر جلسة + result | `app.sessions.first.startedAt` + `.quickResult` (موجود كـ `lastSessionDate`) |
| المركز | `app.currentCenter?.name` |
| عدد المتابعات | `app.pendingFollowups.length` |
| واجبات للمراجعة | `app.pendingHomeworkReviewCount` |
| حالة التقييم | `app.studentAssessmentStatus` |
| الأهداف النشطة | `app.activeGoalCount` (مع `app.masteredGoalCount`) |
| عدد الجلسات | `app.sessions.length` |
| متوسط التقدم | `app.studentGoalImprovementRate(student.id)` |
| البرامج | `app.programsForStudent()` |

**البيانات التي تُنقل للأسفل (من `_StudentOverview`):**
- ولي الأمر / هاتفه → يمكن وضعه في قسم "معلومات الطالب" داخل CollapsibleCard أو إضافته في footer صغير
- اسم المستخدم → مخفي أو يُنقل للأسفل
- ملاحظات الملف → تبقى في البطاقة لكن باختصار (سطر واحد) أو في CollapsibleCard

## 5. تفاصيل الدمج لكل عنصر

### 5.1 الصف الأول (الهوية + آخر جلسة)
**يحل محل:**
- السطر الأول من `_StudentOverview` (الاسم + المركز + status)
- زر الرجوع (يبقى لكن فوق البطاقة)

**يضيف جديد:**
- `lastSessionDate` + `quickResult` — هاتان المعلومة غير موجودتين في الجزء العلوي أصلًا، رغم أنهما الأهم للأخصائي.

### 5.2 الصف الثاني (الإحصائيات)
**يحل محل بالكامل:**
- `_ProfileSummary` (6 StatTile → تصبح 6 AppPill في صف واحد أو صفين)

**التغيير الوحيد:** المعلومة نفسها، فقط بشكل مضغوط أكثر وتحت البطاقة الرئيسية بدل بطاقة مستقلة.

### 5.3 الصف الثالث (البرامج)
**يحل محل:**
- Wrap البرامج داخل `_StudentOverview`

**يبقى كما هو** لكن بعد الدمج في نفس البطاقة.

## 6. البيانات التي تُزال من الجزء العلوي (تُنقل أو تُحذف)

| المعلومة | مصيرها | السبب |
|---|---|---|
| **العمر** | يُنقل إلى داخل بطاقة الطالب (CollapsibleCard جديد في الأسفل) أو يبقى كـ _CompactInfoTile أصغر | ليس أولوية، لكن سهل الإضافة بدون تكلفة |
| **التشخيص** | يُنقل للأسفل | مهم لكن ليس عند فتح الملف لأول مرة |
| **ولي الأمر / هاتفه** | يُنقل للأسفل | يحتاجه الأخصائي للاتصال، ليس لعرض التقدم |
| **اسم المستخدم (البريد)** | يُنقل للأسفل أو يُحذف | يكاد لا يُستخدم |
| **ملاحظات الملف** | تبقى إن وُجدت لكن بسطر واحد | قد تحتوي على تحذيرات مهمة |
| **آخر جلسة لكل هدف** | لا يتأثر — يبقى في `_GoalProgressSection` | دمج الصف العلوي لا يمس المنطق الداخلي للأهداف |
| **نسبة التحسن** اسمها | إعادة تسمية إلى "متوسط تقدم" (فقط تغيير label) | مضلل حاليًا |

## 8. الخلاصة

**البيانات المكررة فعليًا:**
- `_ProfileSummary` تكرر المعلومات التي تظهر في عناوين CollapsibleCards القابلة للتوسيع أسفلها (الأهداف، التقييم، الواجبات)

**البيانات التي يمكن دمجها في بطاقة واحدة:**
- كل ما في `_StudentOverview` + كل ما في `_ProfileSummary` → بطاقة علوية واحدة

**البيانات المفقودة من الجزء العلوي (يحتاجها الأخصائي أولاً):**
- آخر جلسة (تاريخ + نتيجة) — غير موجودة
- عدد المتابعات المفتوحة — غير موجود
- هاتان المعلومتان **متاحتان** في `app.lastSessionDate` و `app.pendingFollowups.length` لكن لا تُستخدمان في Header

**ما لا يتغير (وما زال مهمًا في الأسفل):**
- تفاصيل الأهداف والمهارات والمتابعات — تبقى في `_CollapsibleCard` كما هي
- قائمة الجلسات والتقارير — لا تتأثر

**التغيير الوحيد هو التجميع البصري** — لا تغيير في أي مصدر بيانات أو منطق أو API.
