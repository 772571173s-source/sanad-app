# تحليل شاشة ملف الطالب (StudentProfileScreen)

---

## 1. ما وظيفة شاشة ملف الطالب؟

**من يستخدمها؟**
الأخصائي بشكل أساسي. ولي الأمر يرى نسخة مبسطة (شاشة `_ParentStudentProfile`) إذا كان `app.isParent == true`.

**كيف يدخل إليها؟**
يختار طالبًا من القائمة → `app.selectStudent(student)` ← تُحمّل كل بيانات الطالب (جلسات، خطط، مهارات، تقييمات، واجبات، متابعات، تقارير، مكافآت). الشاشة نفسها تستخدم `selectedStudent` فقط في `_ProfileSummary` و `_QuickActions`.

**هل تعتمد على selectedStudent؟**
نعم. إذا كان `null`، تظهر شاشة اختيار الطالب (`_StudentSelectionPrompt`).一旦 تم اختيار طالب، الشاشة تبني كل الـ summary strings في `build()` من `app.plans`، `app.sessions`، `app.exercises`، `app.clinicalAssessments`، إلخ.

**هل هي للأخصائي فقط أم تظهر لأدوار أخرى؟**
للأخصائي ومدير المركز والمشرف الفني — أي دور لديه صلاحية `viewStudents`. لولي الأمر تظهر نسخة مبسطة لا تحتوي على أهداف أو متابعات أو تقييمات، فقط: معلومات الطالب، الواجبات، الجلسات المكتملة، والملاحظات.

---

## 2. ما الأقسام الموجودة حاليًا؟

كل الأقسام من النوع `_CollapsibleCard` (قابلة للطي) فيما عدا `_StudentOverview`, `_ProfileSummary`, `_QuickActions`, `_PreviousSessions`, `_ReportsFromProfile`.

### 2.1 بيانات الطالب (`_StudentOverview`)
- **ماذا يعرض؟** اسم الطالب، اسم المركز، الحالة (Chip)، البرامج المسجلة (شريحة program)، العمر، التشخيص، ولي الأمر، رقم ولي الأمر، البريد، ملاحظات الملف
- **مصدر البيانات:** `student` (من `app.selectedStudent`) و `app.programsForStudent()`
- **تفاعلي؟** لا، مجرد عرض. زر "رجوع لاختيار طالب آخر" خارج هذا القسم (في `build()`).
- **عند الضغط؟** لا يوجد ضغط.

### 2.2 ملخص التقدم (`_ProfileSummary`)
- **ماذا يعرض؟** 6 بطاقات إحصائية: حالة التقييم، الأهداف النشطة، الأهداف المتقنة، نسبة التحسن، عدد الجلسات، واجبات للمراجعة
- **مصدر البيانات:**
  - `app.studentAssessmentStatus` (هل يوجد تقييم علاجي؟)
  - `app.studentGoalImprovementRate(student.id)` ← متوسط progress لكل الخطط
  - `app.activeGoalCount`, `app.masteredGoalCount` ← بناءً على `progress < 100`
  - `app.sessions.length`
  - `app.pendingHomeworkReviewCount`
- **تفاعلي؟** لا.

### 2.3 التقييم العلاجي (`_ClinicalAssessmentProfileSection`)
- **ماذا يعرض؟** آخر 3 تقييمات علاجية مع: التاريخ، عدد نقاط الضعف، ملخص القوة، ملخص الضعف، ملخص الأهداف
- **مصدر البيانات:** `app.clinicalAssessments` + `app.clinicalFindingsByAssessment[assessment.id]`
- **تفاعلي؟** لا، مجرد عرض. لا يوجد زر لفتح التقييم أو إنشاء تقييم جديد.
- **عند الضغط؟** القابل للطي فقط (expand/collapse).

### 2.4 الأهداف النشطة (`_GoalProgressSection`)
- **ماذا يعرض؟** كل `TrainingPlan` حيث `progress < 100`. لكل هدف: عنوان الهدف، case status (AppPill)، شريط تقدم خطي، إحصائيات (تقدم %، متقن، متبقي، آخر جلسة)، قائمة بكل `GoalSkillStep` مع حالتها وأيقونة، زر "إعادة التدريب" للمهارات التي لديها `pendingFollowup`
- **مصدر البيانات:** `app.plans` (تصفية `where((p) => p.progress < 100)`) + `app.stepsForGoal(plan.id)` + `app.goalProgress(plan.id)` + `app.goalStatus(plan.id)` + `app.pendingFollowups`
- **تفاعلي؟** نعم (جزئيًا):
  - **إعادة التدريب لكل مهارة:** يفتح جلسة جديدة مع `preselectSession` → يستدعي `onOpenSession?.call()`
  - **إعادة التدريب للهدف كامل:** للأهداف بدون خطوات (`steps.isEmpty`), يفتح جلسة الهدف كامل
  - القائمة نفسها غير قابلة للضغط (لا يفتح تفاصيل الهدف)

### 2.5 الأهداف المنجزة (`_MasteredGoalsSection`)
- **ماذا يعرض؟** كل `TrainingPlan` حيث `progress >= 100`. مشابه للأهداف النشطة لكن بحالة "مكتمل" وبدون خطوات مهارية أو أزرار إعادة تدريب
- **مصدر البيانات:** `app.plans` (تصفية `where((p) => p.progress >= 100)`)
- **يظهر فقط إذا:** `plans.any((p) => p.progress >= 100)`
- **تفاعلي؟** لا.

### 2.6 يحتاج إعادة تدريب (`_FollowupsSection`)
- **ماذا يعرض؟** قائمة `pendingFollowups` مع اسم المهارة، اسم الهدف، سبب المتابعة ("بمساعدة" أو "يحتاج إعادة")، تاريخ آخر تحديث، وزر "إعادة التدريب"
- **مصدر البيانات:** `app.pendingFollowups` (وهي `studentFollowups.where((f) => f.status == 'pending')`)
- **يظهر فقط إذا:** `followups.isNotEmpty`
- **تفاعلي؟** نعم — زر إعادة التدريب يفتح جلسة مع `preselectSession` (studentId, programId, sourceType, planId, stepId)

### 2.7 الواجبات المنزلية (`_HomeworkSummary`)
- **ماذا يعرض؟** 3 أقسام: بانتظار ولي الأمر، تحتاج مراجعة، تمت مراجعتها. لكل قسم: عدد الواجبات وقائمة بها
- **مصدر البيانات:** `app.exercises` (تصفية حسب `e.status`)
- **تفاعلي؟** نعم — زر "مراجعة" لكل واجب بحالة `completed_by_parent` (يُحدث `GoalSkillStep.status` إلى "متقن" أو `TrainingPlan.progress` إلى 100)

### 2.8 ملاحظات ولي الأمر (`_ParentNotesCard`)
- **ماذا يعرض؟** الواجبات التي تحتوي على `parentNote.isNotEmpty`
- **مصدر البيانات:** `exercises.where((e) => e.parentNote.isNotEmpty)`
- **تفاعلي؟** لا.

### 2.9 الخط الزمني (`_Timeline`)
- **ماذا يعرض؟** جميع الأحداث (جلسات، تقييمات أسبوعية، تقييمات علاجية، واجبات، تقارير، مكافآت) مرتبة تنازليًا حسب التاريخ
- **مصدر البيانات:** `app.sessions` + `app.evaluations` + `app.clinicalAssessments` + `app.exercises` + `app.reports` + `app.reward`
- **تفاعلي؟** لا.

### 2.10 الإجراءات السريعة (`_QuickActions`)
- **ماذا يعرض؟** أزرار: "تقرير مختصر" (آخر 7 أيام)، "اختبار جلسة محددة" (غير مفعل)، "تقرير شامل" (كل الجلسات)
- **تفاعلي؟** نعم — يفتح حوار اختيار جلسة للتقرير المختصر، أو يولد PDF مباشر للشامل
- **الأزرار معطلة إذا:** `!app.canViewReports`

### 2.11 الجلسات السابقة (`_PreviousSessions`)
- **ماذا يعرض؟** كل `app.sessions` مع: cardTitle, successRate, التاريخ, النوع, quickResult, الأنشطة, الملخص, ملاحظات الأخصائي
- **مصدر البيانات:** `app.sessions` (كلها)
- **تفاعلي؟** لا.

### 2.12 التقارير (`_ReportsFromProfile`)
- **ماذا يعرض؟** كل `app.reports` مع: نوع التقرير، نسبة التقدم، التاريخ
- **مصدر البيانات:** `app.reports`
- **تفاعلي؟** لا.

## 4. كيف تظهر الأهداف؟

**التمييز بين نشط ومنجز:**
- **نشط:** `plan.progress < 100` ← يظهر في `_GoalProgressSection`
- **منجز:** `plan.progress >= 100` ← يظهر في `_MasteredGoalsSection`

**هل يعتمد على progress؟**
نعم. هذا هو المعيار الوحيد للتمييز بين القسمين.

**هل يعتمد على GoalSkillStep.status؟**
غير مباشر. `goalStatus(goalId)` يستخدم steps لتحديد تسمية الحالة (مكتمل، يحتاج إعادة، يحتاج مساعدة، قيد العلاج، جديد). لكن الفصل بين نشط/منجز يعتمد فقط على `progress`.

**هل يظهر الهدف إذا كان بمساعدة؟**
نعم، يظهر في الأهداف النشطة. حالته ستكون "يحتاج مساعدة".

**هل يظهر الهدف إذا يحتاج إعادة؟**
نعم، يظهر في الأهداف النشطة. حالته ستكون "يحتاج إعادة".

**هل يختفي فقط إذا صار متقن بالكامل؟**
نعم، ينتقل إلى الأهداف المنجزة فقط عندما `progress >= 100`.

**هل أهداف الحروف وأهداف الأقسام تظهر بنفس الطريقة؟**
نعم، كلاهما من نوع `TrainingPlan`. الفرق الوحيد هو:
- أهداف الحروف (`sourceType: 'speechSound'`) لها `GoalSkillStep` (الخطوات العلاجية)
- أهداف الأقسام (`sourceType: 'standard'`) قد تكون بدون `GoalSkillStep` (إذا لم يكن هناك `templateSteps` في التقييم)

الأهداف بدون خطوات تظهر العلاج مباشرة (حقل `plan.treatment`) وزر "إعادة التدريب" للهدف كامل.

## 5. كيف تظهر المهارات داخل الهدف؟

**هل كل المهارات تظهر؟**
نعم، كل `stepsForGoal(planId)` تظهر (مرتبة حسب `sortOrder`).

**هل تظهر حالتها؟**
نعم، كـ `step.status` مع أيقونة:
- `متقن` ← أيقونة صح خضراء
- `يحتاج إعادة` (عند وجود followup pending) ← أيقونة تحديث برتقالية + زر "إعادة التدريب"
- غير ذلك ← دائرة غير محددة (radio_button_unchecked)
- النص: `{step.title} - {step.status}`

**هل تظهر آخر جلسة أو آخر نتيجة؟**
فقط كـ "آخر جلسة: التاريخ" على مستوى الهدف (باستخدام `_lastSessionDate` التي تقرأ `lastSessionId` من الـ steps وتجد الجلسة في `app.sessions`). لا تظهر آخر نتيجة لكل مهارة على حدة.

**هل يوجد زر إعادة تدريب لكل مهارة؟**
نعم، فقط للمهارات التي لديها `pendingFollowup`. الزر يستدعي `_openRetrain` الذي:
1. يختار الطالب
2. يستدعي `preselectSession` مع `stepId`
3. يستدعي `onOpenSession?.call()`

**هل هذا مناسب للمنطق الجديد؟**
نعم، `preselectSession` مع `stepId` يضمن فتح الجلسة للمهارة المحددة فقط. لكن المشكلة: إذا كانت المهارة قد أُتقنت لاحقًا بعد إنشاء المتابعة، زر إعادة التدريب ما زال يظهر لأن `pendingFollowups` لم تُحل تلقائيًا.

**ما يحتاج تعديل لاحقًا:**
- زر إعادة التدريب يظهر حتى لو أُتقنت المهارة (لأن الـ followup لم يُresolve)
- الـ steps تظهر حتى في الأهداف المنجزة (لكنها لا تظهر حاليًا لأن `_MasteredGoalsSection` لا يعرض الـ steps)

## 6. المتابعات وإعادة التدريب

**أين تظهر المتابعات؟**
في قسمين:
1. قسم مستقل "يحتاج إعادة تدريب" (`_FollowupsSection`) — يظهر فقط إذا `followups.isNotEmpty`
2. داخل كل هدف نشط — كل `GoalSkillStep` يظهر له زر "إعادة التدريب" إذا كان لديه pending followup

**كيف تُحسب؟**
`app.pendingFollowups` = `studentFollowups.where((f) => f.status == 'pending')`. تُنشأ في `saveSession` عندما تكون result المهارة غير متقنة (يحتاج إعادة أو بمساعدة).

**هل تظهر كقائمة أم عدد فقط؟**
قائمة كاملة في قسم المتابعات، وداخل كل هدف في خطواته.

**هل زر إعادة التدريب يفتح جلسة الهدف كاملة أم مهارة واحدة؟**
- للمهارة: `preselectSession` مع `stepId` ← يفتح الجلسة للمهارة المحددة فقط
- للهدف بدون خطوات: `preselectSession` بدون `stepId` ← يفتح الجلسة للهدف كامل
- من قسم المتابعات: `preselectSession` مع `stepId` (لأن المتابعة مرتبطة بمهارة)

**هل يستخدم sessionPreselect؟**
نعم، كل حالات إعادة التدريب تستخدم `app.preselectSession(target)`.

**هل يرجع للملف بعد الانتهاء؟**
هذا يعتمد على `onOpenSession` — ليس جزءًا من ملف الطالب نفسه. `onOpenSession` هو callback يُمرر من الشاشة الأب (والذي عادة ما يفتح `SessionsScreen`). لا يوجد logic تلقائي للعودة.

## 7. الجلسات داخل ملف الطالب

**هل تظهر كل الجلسات؟**
نعم، كل `app.sessions` تظهر في قسم "الجلسات السابق" وفي "الخط الزمني".

**هل تظهر عدد الجلسات؟**
نعم، في `_ProfileSummary` (StatTile: عدد الجلسات).

**هل تظهر آخر جلسة؟**
نعم، لكل هدف في `_GoalProgressSection` سطر "آخر جلسة: التاريخ".

**هل الجلسات الآن محسوبة على مستوى الهدف؟**
في `_lastSessionDate`، نعم — تبحث عن الجلسات المرتبطة بـ `step.lastSessionId` (مستوى المهارة). لكن في `_ProfileSummary`، `app.sessions.length` هو عدد كل الجلسات.

**هل الملف يعكس المنطق الجديد للجلسات؟**
ليس بالكامل. الجلسات الآن على مستوى المهارة (`skillId` + `planId`)، لكن الملف لا يزال يظهر الجلسات بشكل خطي (list + timeline). الفصل حسب الهدف/المهارة ليس موجودًا في عرض الجلسات.

**هل يوجد تضارب بسبب أن الجلسات سابقًا كانت على مستوى المهارة؟**
نعم، `_lastSessionDate` تفترض أن `step.lastSessionId` يشير إلى جلسة واحدة لكل مهارة، وهو صحيح في المنطق الجديد. لكنها لا تُظهر سوى آخر جلسة للهدف ككل، وليس لكل مهارة آخر جلسة لها.

---

## 8. التقييمات داخل ملف الطالب

**هل تظهر التقييمات السابقة؟**
نعم، آخر 3 تقييمات علاجية في قسم "التقييم العلاجي".

**هل يمكن رؤية أكثر من تقييم؟**
يُعرض `take(3)` فقط. الباقي مخفي (حتى مع توسيع القسم).

**هل يوجد مقارنة بين تقييمين؟**
لا.

**هل يظهر ملخص نقاط القوة والضعف؟**
نعم، `strengthsSummary`, `weaknessesSummary`, `goalsSummary` تظهر لكل تقييم (مقتطف 3 أسطر).

**هل يظهر ClinicalFindings؟**
يُستخدم فقط لحساب `weaknesses.length` (عدد الـ findings غير الطبيعية). التفاصيل الكاملة للـ findings لا تظهر.

**هل التقييمات المتكررة تظهر بشكل مفهوم؟**
يُعرض كل تقييم كبطاقة مستقلة مع تاريخه، لكن لا يوجد مقارنة بصرية أو تتبع للتغير بين التقييمات.

## 9. النقاط والمكافآت

**هل تظهر النقاط؟**
- في ملف ولي الأمر: reward level و xp يظهران في `_InfoTile`
- في ملف الأخصائي: لا يوجد عرض مباشر للنقاط (فقط في الـ Timeline كعنصر واحد "مكافآت ونقاط")

**من أين تأتي؟**
`app.reward` (يُحمّل في `selectStudent` من `sanad_repository.reward(student.id)`)

**هل تأتي من الجلسات فقط الآن؟**
نعم. `_grantXp` يُستدعى فقط من `saveSession`:
- متقن → +2 XP
- بمساعدة → +1 XP
- خطأ → 0 XP

**هل تظهر للأخصائي أم ولي الأمر؟**
تظهر بشكل محدود جدًا للأخصائي (فقط في الـ Timeline). وتظهر بشكل كامل لولي الأمر.

**هل هناك خطر أن تُفهم كنسبة علاجية؟**
الخطر ضعيف، لأن النقاط لا تظهر للأخصائي بشكل بارز. لكن وجودها في الـ Timeline قد يسبب التباسًا.

## 10. الواجبات

**هل تظهر الواجبات؟**
نعم، في قسم "الواجبات المنزلية" (مقسمة إلى 3 حالات).

**هل هي مرتبطة بالجلسات؟**
نعم، كل واجب لديه `planId` و `goalSkillStepId` و `createdFromSessionResult`. لكن الملف لا يُظهر هذه العلاقة بشكل مرئي (مثلاً "هذا الواجب ناتج عن جلسة تاريخ X").

**هل هي يدوية؟**
نعم، تنشأ يدويًا من شاشة الواجبات أو تلقائيًا بعد الجلسة (من `createdFromSessionResult`).

**هل تظهر حالة ولي الأمر؟**
نعم، `parentNote` و `parentCompletedAt` تظهران في بطاقة الواجب.

**هل يوجد زر إنشاء واجب من ملف الطالب؟**
لا. لا يوجد زر "إنشاء واجب" في الملف. الإجراءات السريعة لا تحتوي على هذا الخيار.

## 11. المشاكل والمخاطر الحالية

### 11.1 هل الشاشة ما زالت مبنية على منطق قديم؟
نعم، جزئيًا. الشاشة لا تزال تفترض أن:
- الجلسات كلها على مستوى الطالب (تعرض `app.sessions` كلها)
- الـ `progress` يأتي من `plan.progress` مباشرة (قبل تعديل `goalProgress`)
- كل هدف له خطوات (تظهر `steps` في كل هدف نشط)

### 11.2 هل تفترض أن كل مهارة جلسة؟
نعم جزئيًا. `_lastSessionDate` تفترض أن لكل خطوة `lastSessionId` يشير إلى جلسة، وهذا صحيح للمنطق الجديد (مهارة واحدة لكل جلسة). لكن `_PreviousSections` يعرض كل الجلسات خطيًا، لا يربط الجلسات بالمهارات.

### 11.3 هل الأهداف النشطة والمنجزة صحيحة؟
**مشكلة:** تعتمد فقط على `plan.progress`. المشكلة هي:
- `progress` يُحسب من `goalProgress(goalId)` ← إذا `steps.isEmpty`، يرجع `plan.progress` (القيمة المخزنة في DB). إذا كانت القيمة المخزنة قديمة (مثلاً كانت 100 قبل تعديل `saveClinicalAssessment` الذي لا يضبط progress)، قد يكون الهدف منجزًا بالخطأ.
- `progress` للأهداف بدون خطوات لا يُحدّث إلا إذا استُدعي `updatePlanProgress` يدويًا.
- بعد تعديل `goalStatus()` لقراءة `quickResult` من آخر جلسة، حالة الهدف تصبح أكثر دقة، لكن `progress` يبقى في DB وقد لا يعكس الواقع.

### 11.4 هل عدد الجلسات صحيح؟
`app.sessions.length` يعرض كل الجلسات. هذا صحيح على مستوى الطالب، لكنه لا يعطي صورة واضحة عن عدد الجلسات لكل هدف.

### 11.5 هل المتابعات تظهر بشكل واضح؟
نعم، لكن هناك مشكلتان:
- المهارات التي لديها followup pending تظهر مرتين (في قسم المتابعات + داخل الهدف). هذا ازدحام.
- إذا أُتقنت المهارة (تم تغيير status إلى "متقن") لكن الـ followup لم يُresolve، زر إعادة التدريب ما زال يظهر.

### 11.6 هل إعادة التدريب مناسبة للمنطق الجديد؟
نعم، استخدام `preselectSession` مع `stepId` صحيح. لكن `preselectSession` لا يُمسح تلقائيًا بعد الاستخدام (يحتاج `clearSessionPreselect` عند الدخول إلى شاشة الجلسات).

### 11.7 هل يوجد ازدحام UI؟
نعم:
- 12 قسمًا في صفحة واحدة (بما في ذلك الأقسام المشروطة)
- كلها في `Column` واحد بدون تبويب
- المهارات داخل كل هدف تظهر كلها (قد تكون 10-15 مهارة لكل هدف)
- الجلسات السابقة تعرض كل الجلسات (قد تكون عشرات)
- الـ Timeline يعرض كل الأحداث في قائمة واحدة

### 11.8 هل يوجد أي بيانات مهمة مخفية؟
نعم:
- `ClinicalFinding` التفصيلية لا تظهر (فقط عدد نقاط الضعف)
- آخر 3 تقييمات فقط (ما قبلها مخفي)
- لا تظهر نتائج آخر جلسة لكل هدف
- لا تظهر ملاحظات الجلسات لكل هدف
- لا تظهر `improvementRate` الحقيقي (المعروض هو متوسط progress وليس نسبة تحسن فعلية)

### 11.9 هل يوجد اعتماد على loadHome أو selectStudent ثقيل؟
نعم، `selectStudent` يحمّل 8+ مصادر بيانات منفصلة (sessions, evaluations, plans, goalSkillSteps, exercises, reports, clinicalAssessments + findings لكل تقييم, reward, studentProgramIds). هذا 10-15+ استعلام SQLite للطالب الواحد. في مركز به 100+ طالب، هذا قد يسبب بطئًا إذا تم التبديل بين الطلاب بشكل متكرر.

## 12. ما الذي يحتاجه الأخصائي فعليًا من ملف الطالب؟

أول 5 أشياء يجب أن يعرفها الأخصائي فور فتح الملف:

1. **ما هي الأهداف النشطة وما تقدم كل هدف؟** — موجود (نشط/منجز + progress + steps)، لكنه مزدحم.
2. **متى كانت آخر جلسة وماذا كانت النتيجة؟** — موجود على مستوى الهدف، لكن ليس لكل مهارة. والجلسات السابقة تظهر كلها بدون تركيز على آخر جلسة لكل هدف.
3. **هل هناك متابعات مفتوحة؟** — موجود، لكنه يظهر بنفس مستوى أهمية الأهداف النشطة.
4. **هل الطالب مقيم؟ وما هي نقاط الضعف الرئيسية؟** — موجود، لكن عدد التقييمات محدود بـ 3.
5. **هل هناك واجبات تحتاج مراجعة؟** — موجود.

**ما ينقص:**
- ملخص سريع (1-2 سطر) عن آخر جلسة للطالب عامة (وليس لكل هدف)
- زر بدء جلسة للطالب مباشرة (بدون الدخول لشاشة الجلسات)
- إظهار النتيجة الإجمالية للطالب (تحسن حقيقي وليس متوسط progress)

## 13. اقتراحات مستقبلية (بدون تنفيذ)

### 13.1 إعادة ترتيب الأقسام
ترتيب المقترح:
1. بطاقة الطالب (معلومات أساسية)
2. ملخص سريع (آخر جلسة، متابعات مفتوحة، واجبات للمراجعة)
3. الأهداف النشطة (مطوية افتراضيًا)
4. المتابعات (مطوية، تظهر العدد فقط)
5. التقييمات (مطوية)
6. الواجبات (مطوية)
7. الجلسات السابقة (مطوية)

### 13.2 تحويل الملف إلى Timeline علاجي
استبدال القسم الحالي بتايملاين تفاعلي مع:
- فلترة حسب النوع (جلسات/تقييمات/واجبات)
- إمكانية الضغط على أي حدث لفتح التفاصيل
- عرض تقدم كل هدف على طول الخط الزمني

### 13.3 بطاقة ملخص عليا
بطاقة واحدة في أعلى الملف تظهر:
- حالة الطالب (مقيم/غير مقيم)
- آخر جلسة (التاريخ + quickResult)
- عدد المتابعات المفتوحة
- عدد الواجبات للمراجعة
- التحسن العام (بحساب حقيقي وليس متوسط progress)

### 13.4 تبويب أهداف / جلسات / تقييمات / واجبات
استخدام `TabBar`:
- **الأهداف:** قائمة الأهداف مع تفاصيلها
- **الجلسات:** قائمة الجلسات (مع فلترة حسب الهدف)
- **التقييمات:** قائمة التقييمات (مع مقارنة إذا أمكن)
- **الواجبات:** قائمة الواجبات (مقسمة حسب الحالة)

### 13.5 زر بدء جلسة من الهدف
إضافة زر "بدء جلسة" بجانب كل هدف مباشرة في قائمته (بدون الحاجة للدخول إلى شاشة الجلسات واختيار الهدف).

### 13.6 مقارنة تقييمات
إضافة عرض مقارن بين آخر تقييمين:
- تطور نقاط القوة والضعف
- تغير الـ finding status (isNormal)
- تقدم ملخص الأهداف

### 13.7 عرض progress حقيقي
حساب improvement حقيقي بناءً على:
- مقارنة نتائج أول تقييم بآخر تقييم
- تحليل اتجاه successRate في الجلسات
- ليس مجرد متوسط progress للخطط

### 13.8 عرض followups بشكل أوضح
فصل المتابعات إلى:
- "يحتاج إعادة" (سبب retry)
- "بمساعدة" (سبب assisted)
- إظهار عدد المرات التي أُعيد فتح فيها كل متابعة
- حل تلقائي للمتابعة عند إتقان المهارة

## 14. خلاصة تنفيذية

**هل ملف الطالب يعكس النظام الجديد؟**
جزئيًا. الشاشة تُظهر كل البيانات الصحيحة، لكنها لا تزال مبنية على نموذج العرض الخطي القديم. العلاقة بين الجلسات والأهداف والمهارات غير واضحة للمستخدم. التعديل السابق على `goalStatus()` يحسّن دقة حالة الهدف، لكن `progress` يبقى قديمًا لبعض الحالات.

**أين أكبر مشكلة؟**
أكبر مشكلة هي **الازدحام وعدم التبويب**. 12 قسمًا في `Column` واحد يجعل الملف طويلاً جدًا. الأخصائي يحتاج إلى التمرير كثيرًا للوصول للمعلومة التي يريدها. ثاني أكبر مشكلة هي أن **الأهداف بدون `GoalSkillStep` ليس لها progress ديناميكي** — `progress` يُقرأ من DB وقد لا يتغير إلا يدويًا.

**ما أول تعديل تنصح به؟**
إضافة `TabBar` بسيط مع 3-4 تبويبات رئيسية:
1. **الأهداف** (نشطة + منجزة + متابعات)
2. **الجلسات** (قائمة + آخر جلسة لكل هدف)
3. **التقييمات والواجبات** (معًا تحت تبويب واحد)
4. **الملخص** (البيانات الأساسية + الإجراءات السريعة)

هذا سيحل مشكلة الازدحام فورًا دون تغيير أي مصدر بيانات أو منطق.

**ما الذي نؤجله؟**
- مقارنة التقييمات (يتطلب حساب تحسن حقيقي)
- عرض `ClinicalFinding` التفصيلي (يحتاج إعادة تصميم)
- العرض الزمني المتقدم (يحتاج تحليل أعمق)
- تحويل `progress` إلى حساب ديناميكي كامل (يحتاج تغيير في `syncGoalProgress` ليشمل الأهداف بدون خطوات)
